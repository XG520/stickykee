# 打包指南（三端构建 / 迭代发布）

> 适用项目：Sticky Kee / 糯米（`cn.stickykee.app`）
> 三端构成：**前端** `app/`（Vue3 + Vite）→ **后端** `server/`（Go，托管前端 dist）→ **APK** `apk/`（Capacitor 壳，壳页独立引导，远程加载服务器页面）
> 最近一次迭代：**v1.2.1**（2026-10-14，统一 APK 签名入库）

## 一、版本号同步（每次发版必改 3 处）

| 端 | 文件 | 字段 |
|---|---|---|
| 前端 | `app/package.json` | `version` |
| APK | `apk/android/app/build.gradle` | `versionCode`（每次 +1）、`versionName` |
| 后端 | `server/internal/api/handler/health_prefs.go` | `const Version`（经 `/healthz` 暴露，设置页/壳页用来核对版本） |

三处保持同号；`versionCode` 单调递增即可（当前 14 ↔ 1.2.1）。

## 二、前端构建（app/dist）

```powershell
cd <仓库根>\app
npm run build          # vite build，产物在 app\dist\
```

- 产物：`<仓库根>\app\dist\`（由后端 `SN_STATIC_DIR` 指向托管，含 SPA 回退）
- 注意 `vite.config` 的 `base` 必须为绝对 `'/'`（相对基址在深层路由刷新会白屏）
- 只改前端时的发布 = 重新 build + 把 `dist/` 更新到服务器静态目录（部署需单独执行，见第五节）

## 三、后端编译（server）

```powershell
cd <仓库根>\server
go build -o ..\release\stickykee-server-1.1.0-windows-amd64.exe ./cmd/server
```

- 产物：`<仓库根>\release\stickykee-server-<版本>-windows-amd64.exe`
- Linux/Docker 部署走根目录 `Dockerfile`（node 构建前端 → go 编译 → alpine 运行，数据在 `/data` 卷）；本机未装 Docker 时用上命令出 Windows exe
- 验证：运行后 `curl http://127.0.0.1:<port>/healthz` 应返回 `{"status":"ok","version":"1.1.0"}`

## 四、APK 打包（Capacitor 壳）

壳页是**独立引导页**（`apk/www/index.html`，原生 JS 无框架，负责服务器地址簿/探测/跳转），
`webDir: "www"` —— **APK 不包含 `app/dist`**，主页面从服务器远程加载。因此：

- 改 `app/` 前端代码 → 只需第二节重新构建 + 服务器更新 dist，**无需重打 APK**
- 改 `apk/www/` 壳页、原生层（MainActivity / build.gradle / 权限等）、Capacitor 配置 → 必须重打 APK

打包命令（debug 签名包，可直接安装）：

```powershell
cd <仓库根>\apk
npm run cap:sync                                  # 同步壳页 www/ → android assets
cd android
# gradlew 依赖 JDK 17，先安装 JDK 并把 JAVA_HOME 指向它（未设置会报
# "JAVA_HOME is not set" 退出）
$env:JAVA_HOME = 'C:\path\to\jdk-17'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat assembleDebug --console=plain       # 产物 app-debug.apk
```

产物链：

| 阶段 | 路径 |
|---|---|
| gradle 原生产物 | `apk\android\app\build\outputs\apk\debug\app-debug.apk` |
| 本地归档（带版本号） | `<仓库根>\release\stickykee-<版本>.apk`（如 `stickykee-1.1.0.apk`） |
| Docker 镜像内置（**固定名，Docker 构建输入**） | `<仓库根>\release\stickykee-app.apk` |

```powershell
# 本地归档（带版本号，便于追溯）
Copy-Item apk\android\app\build\outputs\apk\debug\app-debug.apk release\stickykee-1.1.0.apk -Force
# Docker 合一镜像内置 APK：根 Dockerfile 第 45 行 COPY release/stickykee-app.apk → /var/apk/，
# 经 SN_APK_FILE 供设置页「系统信息」与 /api/v1/app/download 下载。重新 docker build 前
# 务必用最新产物覆盖这个固定名文件（带版本号的文件不会被 COPY）：
Copy-Item apk\android\app\build\outputs\apk\debug\app-debug.apk release\stickykee-app.apk -Force
```

注意：Docker 构建只认固定名 `stickykee-app.apk`；该文件缺失时 `docker build` 直接失败——
暂不内置 APK 时可按 Dockerfile 注释注释掉 `COPY` 行与 `SN_APK_FILE`，下载入口自动关闭。

### 统一签名（所有机器产物签名一致）

签名密钥已固化入仓库：`apk\android\app\stickykee.keystore`（别名 `androiddebugkey`，store/key 密码均为 `android`，即项目首次打包机器的 debug 密钥）。`build.gradle` 中 `signingConfigs.stickykee` 同时作用于 **debug 与 release**：

- 任何机器 `git pull` 后直接打包，产物签名一致，可互相覆盖安装，不再依赖各机器 `%USERPROFILE%\.android\debug.keystore`（此前换机器打包签名不一致、覆盖安装报「签名不对」的根源）
- `assembleRelease` 产物也已签名（`app-release.apk`，可直接安装），不再是 `app-release-unsigned.apk`
- **不要删除或更换该 keystore**：签名一变，已安装的包只能卸载重装（应用数据丢失）
- 指纹核对：SHA1 `ED:3E:E4:D0:EC:CB:5A:17:81:96:45:46:13:2C:00:12:A1:BB:BD:99`

```powershell
# 校验任意 APK 的签名是否与仓库 keystore 一致
& "$env:JAVA_HOME\bin\keytool.exe" -printcert -jarfile release\stickykee-1.2.1.apk | Select-String "SHA1:"
```

若手机已装的是其他签名的包（曾在别的机器打包安装过），覆盖安装会报签名冲突——需先卸载旧包（数据会清空）再装新包。

要点：

- 签名：仓库内统一 keystore（见上「统一签名」），`assembleDebug` / `assembleRelease` 产物均已签名，可直接 `adb install -r`
- gradle 镜像：`android/build.gradle` 与 `~/.gradle/init.gradle` 双阿里云镜像 + gradle-wrapper 腾讯镜像（国内直连可用，无需代理）
- 壳页配置清单（历史踩坑）：`androidScheme: "http"`、`allowNavigation: ["*"]`、`usesCleartextTraffic=true`，缺一壳页会卡「正在进入」或被 mixed content 拦截
- 装模拟器（MuMu12，adb 端口 `127.0.0.1:16384`）：

```powershell
%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe -s 127.0.0.1:16384 install -r release\stickykee-1.1.0.apk
```

- WebView 远程调试：debug 包自动开启，`adb forward tcp:9333 localabstract:<webview_devtools_remote socket>` 后访问 `http://127.0.0.1:9333/json`

## 五、服务器更新（部署）

> 规则：**仅在明确说「部署」时执行**，日常改动只做构建验证。

部署 = 将 `app/dist/` 更新到服务器静态目录（或重建 Docker 镜像）+ 替换后端二进制 + 重启服务。
服务器部署方式与地址见 `README.md` 与 `server/docker-compose.yml`。

## 六、发版核对清单

1. 三处版本号已同步（第一节表格），`versionCode` +1
2. `app`：`npm run build` 无报错
3. `server`：`go build` 无报错，`/healthz` 版本正确
4. `apk`：`cap:sync` 后 `gradlew assembleDebug` 无报错，产物拷入 `release/`
5. `release/` 归档：`stickykee-<版本>.apk` + `stickykee-server-<版本>-windows-amd64.exe`，并已用最新 APK 覆盖固定名 `stickykee-app.apk`（Docker 构建输入，见第四节）
6. 如改了卡片模板/迁移逻辑：确认 `app/src/utils/dashboard.js` 迁移标记（如翻页时钟 js 含 `v3`）与 `cardDefaults` 模板一致
