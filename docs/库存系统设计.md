# 库存 / 食品库系统设计

> 目标：在 HomeCanvas 中加入「冰箱 / 食品库 / 物品库」库存管理，支持 **扫码、识图、手动** 三种录入，库存数据接入 Home Assistant。

## 1. 结论与范围

- 库存按 **HA 实例（`instance_id`）归属，家庭内所有登录账号共享**；每次变更记录操作人。
- 扫码采用 **Android 原生 ML Kit**（bundled 版，不依赖 GMS），经 `NativeBridge` 暴露给 WebView。
- HA 只发布两个实体：`sensor.hc_inventory_total`（总数）与 `sensor.hc_inventory_expiring`（临期数）。

分期：

| 阶段 | 内容 |
|---|---|
| P1 | 表结构 + CRUD API + 手动添加 + 列表/临期 + HA 总数/临期传感器 |
| P2 | 原生扫码（连续录入）+ 单物品识图 + 购物清单 + 补货点 + FEFO 消耗/开封后保质 |
| P3 | 盘点批量调整、价值统计、导入导出、成员只读、过期/缺货提醒、仪表盘卡片、小票批量识别 |

### 1.1 对标主流系统与取舍

参考 Grocy（自托管家庭库存）、KitchenOwl（食品库存 + 食谱）、Sortly / HomeBox（物品库）以及通用 WMS 的批次/效期模型，采纳与家庭场景匹配的能力，砍掉 ERP 级复杂度。

| 主流能力 | 代表系统 | 采纳 | 说明 |
|---|---|---|---|
| 物品 + 批次 + 效期 | Grocy / WMS | 是 | 批次是临期与 FEFO 的基础（已设计） |
| 购物清单 | Grocy / KitchenOwl / Bring! | 是 | 缺货/临期一键加入，成员共享 |
| 补货点 / 最小库存 | Grocy `min_stock_amount` | 是 | 低于阈值提醒并加入购物清单 |
| 位置层级 | Grocy / Sortly | 是 | 冰箱 → 冷藏/冷冻，支持父子层级 |
| FEFO（先到期先出） | WMS | 是 | 消耗默认扣最早到期批次，减少浪费 |
| 开封后保质期 | Grocy / KitchenOwl | 是 | 开封后按 `after_open_days` 重算到期 |
| 包装规格 / 单位换算 | WMS | 是（轻量） | 入库按包装、库存按基础单位 |
| 本地条码库（多码映射） | Grocy / KitchenOwl | 是 | 离线可用，外部库仅首次补充 |
| 盘点 / 批量调整 | WMS | 是（轻量） | 一次核对多物品数量，生成 adjust 流水 |
| 价值 / 成本统计 | Sortly / ERP | 可选 | 记录入库价，P3 汇总库存价值 |
| 食谱联动推荐 | KitchenOwl / Paprika | 可选 | P3 之后，按库存推荐可做的菜 |
| 供应商 / 采购单 / 多仓调拨 | ERP / WMS | 否 | 家庭单户场景过重 |
| ABC 分类 / 波次拣货 / 成本核算 | ERP | 否 | 无实际收益 |

## 2. 总体架构

```
扫码(ML Kit) / 拍照识图 / 手动
        │
        ▼
InventoryView.vue ──REST──► handler/inventory.go
        │                        │
        │                        ├─ SQLite：items / batches / locations / logs / shopping / barcodes
        │                        ├─ AI vision（复用 ai_config 的 key）
        │                        └─ HA sensor 推送（复用 mobile_app 虚拟设备）
        ▼
  sensor.hc_inventory_total / sensor.hc_inventory_expiring
```

库存是多实例（多 HA）隔离的：切换实例即切换库存视图。

## 3. 数据模型

新增 7 张表，写入 [db.go](../../server/internal/store/db.go) 的 `migrate()`，全部 `CREATE TABLE IF NOT EXISTS`，向后兼容。

```sql
-- 存放位置：冷藏室 / 冷冻室 / 橱柜 / 药箱 …
CREATE TABLE IF NOT EXISTS inventory_locations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'other',      -- fridge/freezer/pantry/medicine/other
  icon TEXT NOT NULL DEFAULT '',
  ha_entity_id TEXT NOT NULL DEFAULT '',   -- 可选：关联温度/门磁实体
  parent_id INTEGER NOT NULL DEFAULT 0,    -- 0=顶层；支持 冰箱→冷藏/冷冻 层级
  sort INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 物品主数据（商品维度，条码唯一）
CREATE TABLE IF NOT EXISTS inventory_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  barcode TEXT NOT NULL DEFAULT '',
  category TEXT NOT NULL DEFAULT '',       -- 食品/饮料/药品/日用品
  unit TEXT NOT NULL DEFAULT '件',         -- 件/瓶/盒/g/ml
  image_path TEXT NOT NULL DEFAULT '',
  default_shelf_life_days INTEGER NOT NULL DEFAULT 0,
  after_open_days INTEGER NOT NULL DEFAULT 0,  -- 开封后保质天数，0=不区分
  min_quantity REAL NOT NULL DEFAULT 0,        -- 补货点，低于则提醒/入购物清单
  pack_size REAL NOT NULL DEFAULT 1,           -- 包装规格：1 个包装 = pack_size 个基础单位
  pack_unit TEXT NOT NULL DEFAULT '',          -- 包装名：箱/提/包
  tags TEXT NOT NULL DEFAULT '',               -- 逗号分隔标签
  notes TEXT NOT NULL DEFAULT '',
  created_by TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_inventory_barcode
  ON inventory_items(instance_id, barcode) WHERE barcode <> '';

-- 库存批次（同一物品可有多个过期日）
CREATE TABLE IF NOT EXISTS inventory_batches (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id INTEGER NOT NULL REFERENCES inventory_items(id) ON DELETE CASCADE,
  location_id INTEGER NOT NULL REFERENCES inventory_locations(id),
  quantity REAL NOT NULL DEFAULT 1,
  production_date TEXT NOT NULL DEFAULT '', -- yyyy-mm-dd，可空
  expiry_date TEXT NOT NULL DEFAULT '',     -- yyyy-mm-dd，空=无保质期
  opened INTEGER NOT NULL DEFAULT 0,
  opened_at TEXT NOT NULL DEFAULT '',       -- 开封时间，配合 after_open_days 重算到期
  entry_date TEXT NOT NULL DEFAULT '',      -- 入库日
  entry_price REAL NOT NULL DEFAULT 0,      -- 入库单价（可选，价值统计）
  status TEXT NOT NULL DEFAULT 'active',    -- active/consumed/discarded
  created_by TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_inventory_batches_item ON inventory_batches(item_id);
CREATE INDEX IF NOT EXISTS idx_inventory_batches_expiry ON inventory_batches(status, expiry_date);

-- 进出库流水（统计 / 回溯）
CREATE TABLE IF NOT EXISTS inventory_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  item_id INTEGER NOT NULL DEFAULT 0,
  batch_id INTEGER NOT NULL DEFAULT 0,
  action TEXT NOT NULL,                    -- add/consume/adjust/discard/move
  delta REAL NOT NULL DEFAULT 0,
  quantity_after REAL NOT NULL DEFAULT 0,
  user TEXT NOT NULL DEFAULT '',
  ts_ms INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_inventory_logs_ts ON inventory_logs(ts_ms);

-- 过期提醒去重（同一批次同一天只提醒一次）
CREATE TABLE IF NOT EXISTS inventory_reminders (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  batch_id INTEGER NOT NULL REFERENCES inventory_batches(id) ON DELETE CASCADE,
  remind_date TEXT NOT NULL,              -- yyyy-mm-dd
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(batch_id, remind_date)
);

-- 本地条码库（一个物品可对应多个条码，离线可查）
CREATE TABLE IF NOT EXISTS inventory_barcodes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  barcode TEXT NOT NULL,
  item_id INTEGER NOT NULL REFERENCES inventory_items(id) ON DELETE CASCADE,
  source TEXT NOT NULL DEFAULT 'manual',   -- manual/scan/external
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(instance_id, barcode)
);
CREATE INDEX IF NOT EXISTS idx_inventory_barcodes_item ON inventory_barcodes(item_id);

-- 购物清单（缺货/临期一键加入，成员共享）
CREATE TABLE IF NOT EXISTS inventory_shopping_list (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  item_id INTEGER NOT NULL DEFAULT 0,      -- 0=自由文本项
  name TEXT NOT NULL,
  quantity REAL NOT NULL DEFAULT 1,
  unit TEXT NOT NULL DEFAULT '件',
  note TEXT NOT NULL DEFAULT '',
  done INTEGER NOT NULL DEFAULT 0,
  created_by TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  done_at TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_inventory_shopping_done ON inventory_shopping_list(instance_id, done);
```

**为什么物品与批次分离**：同一商品可能有不同过期日（两盒 11-26 到期、一盒 12-02 到期）。过期判断只作用于批次，列表可按"最近到期批次"排序。

图片存 `server/data/inventory/{item_id}_{ts}.jpg`（`server/data/` 已在 .gitignore），并通过新增的 `/api/v1/inventory-files/*` 静态路由对外提供（参照 `im-files` 的挂载方式）。

全部挂在 [router.go](../../server/internal/api/router.go) 的 `/api/v1` 鉴权组内（下表路径均省略 `/api/v1` 前缀），统一 `{data, meta}` / `{error:{code,message}}` 信封。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/inventory/locations` | 位置列表 |
| POST/PUT/DELETE | `/inventory/locations[/{id}]` | 位置增改删 |
| GET | `/inventory/items?location=&q=&category=&status=&expiring_days=&low_stock=` | 物品+批次聚合列表 |
| POST | `/inventory/items` | 新建物品并带首批次（手动/扫码/识图共用） |
| GET/PUT/DELETE | `/inventory/items/{id}` | 物品详情/编辑/删除 |
| POST | `/inventory/items/{id}/batches` | 追加批次（再次入库） |
| POST | `/inventory/batches/{id}/consume` | `{qty}` 消耗，扣减或置 consumed |
| POST | `/inventory/batches/{id}/open` | 标记已开封（`opened=1`） |
| POST | `/inventory/batches/{id}/discard` | 丢弃 |
| POST | `/inventory/batches/{id}/move` | `{location_id}` 移库 |
| GET | `/inventory/stats` | 总数/临期/已过期/按位置 |
| GET | `/inventory/logs?limit=` | 流水 |
| POST | `/inventory/lookup/barcode` | `{barcode}` 查本地，未命中再查外部 |
| POST | `/inventory/recognize` | 图片 → AI 识图返回结构化候选 |
| GET/POST/PUT/DELETE | `/inventory/shopping-list[/{id}]` | 购物清单增删改查 |
| POST | `/inventory/shopping-list/{id}/check` | `{done}` 勾选完成；可一键完成并入库 |
| POST | `/inventory/items/{id}/to-shopping` | 加入购物清单（已有未完成项则合并数量） |
| POST | `/inventory/stocktake` | 批量盘点 `[{item_id, location_id, quantity}]`，生成 adjust 流水 |
| GET | `/inventory/barcodes/{code}` | 本地条码映射（扫码优先查本地） |
| POST | `/inventory/barcodes` | 绑定条码到物品（支持一物多码） |
| GET | `/inventory/export.csv` | 导出库存（P3） |

新增文件：`server/internal/store/inventory_repo.go`、`server/internal/api/handler/inventory.go`、`server/internal/ha/inventory_sync.go`。

条码联网识别（`GET /inventory/barcodes/{code}/product`）默认查 Open Food Facts；可选接入淘宝开放平台「码上淘」条码库，国内商品覆盖更全。在服务器配置环境变量 `TAOBAO_APP_KEY` / `TAOBAO_APP_SECRET`（open.taobao.com 创建应用即可获得，接口免费且无需用户授权）后自动启用为并行查询源。商品库未收录时，前端仍打开新增表单并提示：填写名称保存后，该条码会随物品记入本地库，下次扫描直接命中。

## 5. 接入 Home Assistant（仅总数 + 临期）

复用生日功能的模式：`stickykee_server_<instance_id>` 虚拟设备 + mobile_app webhook 的 `register_sensor` / `update_sensor_states`（见 [birthdays.go](../../server/internal/api/handler/birthdays.go) 的 `syncOne` 与 `server_device.go` 的 `ServerDevice`）。注册与 webhook 由 `ServerDevice` 统一持有，生日 / 记账 / 库存 / 计划共用同一台 HA 设备；不要各模块自行注册——HA 对同一 `device_id` 再次注册会轮换 webhook，导致其他模块的 webhook 立即失效。

| 实体 | unique_id | 状态 | 属性 |
|---|---|---|---|
| `sensor.hc_inventory_total` | `hc_inv_total` | 在库总件数 | `by_location` 各位置计数 |
| `sensor.hc_inventory_expiring` | `hc_inv_expiring` | 临期件数 | `items[]`：名称/过期日/位置 |

> 上表 entity_id 为期望值，实际由 HA 按 friendly name / 设备名 slugify 生成，注册后应以 HA 返回的 entity_id 为准。

- 每次增删改后异步推送（沿用现有 5s 限频 + 6h 自愈重推）。
- 临期窗口默认 3 天，可在设置中配置（存实例级 `prefs` 的 `inventory_expiring_days`，避免多用户各算各的导致 sensor 值不一致）。
- 这样 HA 自动化即可"牛奶临期 → 灯变红 / 语音播报 / 推送手机"。
- **可选扩展**（默认关闭）：如需在 HA 看到购物清单，可再发布 `sensor.hc_inventory_shopping`（未完成条目数 + `items[]` 名称）。为控制实体数量，默认不注册，需在设置中显式开启。

## 6. 扫码（原生 ML Kit）

**依赖**：ML Kit 用 bundled 版（模型随 APK，不依赖 Google Play 服务，避免国内无 GMS 设备不可用）；`barcode-scanning` 只提供分析器，实时取景需配合 CameraX：

```gradle
implementation 'com.google.mlkit:barcode-scanning:17.3.0'
// CameraX：取景预览 + 帧分析（缺失则无法显示扫描画面）
implementation 'androidx.camera:camera-core:1.3.4'
implementation 'androidx.camera:camera-camera2:1.3.4'
implementation 'androidx.camera:camera-lifecycle:1.3.4'
implementation 'androidx.camera:camera-view:1.3.4'
```

**改动：**

1. [AndroidManifest.xml](../../apk/android/app/src/main/AndroidManifest.xml) 增加：
   ```xml
   <uses-permission android:name="android.permission.CAMERA" />
   <uses-feature android:name="android.hardware.camera" android:required="false" />
   ```
2. [NativeBridge.java](../../apk/android/app/src/main/java/cn/stickykee/app/NativeBridge.java) 增加方法 `scanBarcode()`：
   - 运行时请求 `CAMERA` 权限；
   - 用 ML Kit `BarcodeScanning.getClient()` + CameraX 预览返回首个条码字符串；
   - 注意：项目原生桥是 `WebView.addJavascriptInterface` 注册的 `window.StickyKeeNative`（`@JavascriptInterface`），**不是 Capacitor 插件**。异步结果参照 `speakEdge2` 的 `stickykee-tts` 模式经 window 事件回传（如 `{ req, ok, value, format }`），不要使用 `PluginCall.resolve`。
3. 前端 `BarcodeScanner.vue`：优先调用原生桥；在普通浏览器里回退 `BarcodeDetector` / `@zxing/browser`（非 APK 场景）。
4. 扫码后流程：
   - 先查本地 `inventory_barcodes` / `GET /inventory/barcodes/{code}`，命中 → 直接打开"再入库"面板（选位置/数量/过期日）；未命中再 `POST /inventory/lookup/barcode` 查外部；
   - 未命中 → 可选查外部食品库（OpenFoodFacts，免费，需服务器可访问公网且国内商品覆盖有限）→ 预填表单；外部查询应做成可开关、失败静默回退，仍无则手动补名称。

## 9. 过期与补货提醒

- 后台每小时扫描 `status='active'` 且 `expiry_date` 在窗口内的批次；扫描 goroutine 在服务启动处注册，并在实例删除时停止。
- 推送：HA `persistent_notification`（显示在通知中心）+ mobile_app notify（复用现有通知链路）；不使用聊天组件 `MessageCenter`。
- 去重：`inventory_reminders` 记录「批次 + 提醒日」，同一批次同一天只提醒一次；过期日变化或跨天后再提醒。
- 补货提醒：物品 `min_quantity > 0` 且在库总量低于阈值时提醒，并可一键加入购物清单（清单内已有该物品未完成项时不重复添加）。
- 消耗策略（FEFO）：`consume` 未指定批次时按 `expiry_date` 升序扣减最早到期批次；指定批次则以用户选择为准。

## 11. 风险与约束

- **ML Kit**：必须用 bundled 版（`com.google.mlkit`），unbundled 版（`play-services-mlkit`）依赖 GMS，国内设备会失败。
- **相机权限**：Android 6+ 需运行时申请；WebView 内的原生扫码由原生层处理权限，避免与 Web 权限模型冲突。
- **AI 识图**：依赖用户配置支持 vision 的模型；key 始终留在后端，前端不接触明文。
- **实体数量**：只发 2 个 sensor，避免库存增长导致 HA 实体爆炸。
- **数据隔离**：库存按 `instance_id` 共享，外键 `ON DELETE CASCADE` 保证删除实例时级联清理。
- **单位一致性**：`quantity` 为 `REAL`，`unit` 由物品定义，接口层需校验批次单位与物品一致，避免「盒」「g」混算。
- **外部商品库**：OpenFoodFacts 需公网且国内覆盖有限，应可开关并失败回退手动录入。
- **数量精度**：`quantity` 用 `REAL`，累加/单位换算可能有浮点误差；按个计数的物品建议存整数，或统一以最小单位（g/ml）存整数、展示时换算。
- **购物清单一致性**：清单「完成并入库存」需生成对应批次并记流水，避免重复入库；`item_id=0` 的自由文本项不参与库存。
- **盘点审计**：批量盘点必须逐条写 `adjust` 流水，保留调整前后差异，便于回溯。
