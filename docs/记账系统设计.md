# 记账系统设计（库存页内）

> 目标：在库存页新增「账本」，支持日常收支记账、库存入库自动记账、预算与报表，数据按 HA 实例家庭共享，并发布到 Home Assistant。

## 1. 定位与范围

- 与库存同层：放在 `/inventory` 页的第三个 Tab（库存 / 购物清单 / 账本），共享 `instance_id`，家庭内所有账号可见。
- **库存联动**：物品入库填写单价即自动生成一笔支出；丢弃可选记为「损耗」；购物清单完成后入库同样自动记账。
- **独立记账**：日常吃饭、交通、工资等与库存无关的收支也能记。
- 金额一律用**分（INTEGER）**存储，避免浮点误差。
- 不做的：股票/基金持仓、发票管理、企业报销审批、多人分账结算。

## 3. 数据模型

新增 5 张表，写入 [db.go](../../server/internal/store/db.go) 的 `migrate()`，全部 `CREATE TABLE IF NOT EXISTS`。

```sql
-- 资金账户：现金 / 储蓄卡 / 信用卡 / 支付宝 / 微信 / 其他
CREATE TABLE IF NOT EXISTS fin_accounts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'cash',        -- cash/debit/credit/alipay/wechat/other
  currency TEXT NOT NULL DEFAULT 'CNY',
  opening_balance INTEGER NOT NULL DEFAULT 0, -- 分
  icon TEXT NOT NULL DEFAULT '',
  sort INTEGER NOT NULL DEFAULT 0,
  archived INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 收支分类（parent_id=0 为一级，二级分类挂在下面）
CREATE TABLE IF NOT EXISTS fin_categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'expense',     -- expense/income
  parent_id INTEGER NOT NULL DEFAULT 0,
  icon TEXT NOT NULL DEFAULT '',
  sort INTEGER NOT NULL DEFAULT 0,
  monthly_budget INTEGER NOT NULL DEFAULT 0, -- 分，0=不限
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_fin_categories_type ON fin_categories(instance_id, type, parent_id);

-- 交易流水
CREATE TABLE IF NOT EXISTS fin_transactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  type TEXT NOT NULL DEFAULT 'expense',     -- expense/income/transfer
  amount INTEGER NOT NULL,                  -- 分，恒为正数
  account_id INTEGER NOT NULL REFERENCES fin_accounts(id),
  to_account_id INTEGER NOT NULL DEFAULT 0, -- transfer 的目标账户
  category_id INTEGER NOT NULL DEFAULT 0,
  currency TEXT NOT NULL DEFAULT 'CNY',
  note TEXT NOT NULL DEFAULT '',
  tags TEXT NOT NULL DEFAULT '',            -- 逗号分隔
  source TEXT NOT NULL DEFAULT 'manual',    -- manual/inventory/shopping/ocr
  ref_type TEXT NOT NULL DEFAULT '',        -- inventory_batch/shopping_item
  ref_id INTEGER NOT NULL DEFAULT 0,
  occurred_at TEXT NOT NULL,                -- yyyy-mm-dd HH:MM
  created_by TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at TEXT NOT NULL DEFAULT ''       -- 软删除
);
CREATE INDEX IF NOT EXISTS idx_fin_tx_time ON fin_transactions(instance_id, occurred_at);
CREATE INDEX IF NOT EXISTS idx_fin_tx_category ON fin_transactions(instance_id, category_id, occurred_at);
-- 库存自动记账幂等：同一批次/清单项只生成一笔（软删除后释放，可重新记账）
CREATE UNIQUE INDEX IF NOT EXISTS uq_fin_tx_ref
  ON fin_transactions(instance_id, ref_type, ref_id)
  WHERE ref_type <> '' AND deleted_at = '';

-- 月度预算（按月覆盖分类的默认预算）
CREATE TABLE IF NOT EXISTS fin_budgets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  month TEXT NOT NULL,                      -- yyyy-mm
  category_id INTEGER NOT NULL DEFAULT 0,   -- 0=总预算
  amount INTEGER NOT NULL DEFAULT 0,        -- 分
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(instance_id, month, category_id)
);

-- 周期账单（房租、会员、还款）
CREATE TABLE IF NOT EXISTS fin_recurring (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  instance_id INTEGER NOT NULL REFERENCES instances(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'expense',
  amount INTEGER NOT NULL,
  account_id INTEGER NOT NULL,
  category_id INTEGER NOT NULL DEFAULT 0,
  day_of_month INTEGER NOT NULL DEFAULT 1,
  enabled INTEGER NOT NULL DEFAULT 1,
  last_run_month TEXT NOT NULL DEFAULT '',  -- 去重：已生成的月份
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**账户余额不落库**，实时计算：`opening_balance + Σ(该账户收入) − Σ(该账户支出) − Σ(转出) + Σ(转入)`。

- 转账用**单条** `type='transfer'` 记录：`account_id` 为转出、`to_account_id` 为转入，不写两条镜像流水，避免重复计算。
- 统计收支时排除 `type='transfer'`：转账只影响账户余额，不计入当月支出/收入。

## 4. 与库存/购物清单联动

| 触发 | 生成交易 | 说明 |
|---|---|---|
| 新建批次且 `entry_price > 0` | 支出，`source=inventory`，`ref_type=inventory_batch`，`ref_id=batch_id` | 金额 = `entry_price × quantity`，分类默认「食品」或按物品 `category` 映射 |
| 购物清单「完成并入库」（P2） | 支出，`source=shopping`，`ref_type=shopping_item` | 依赖当前尚未实现的「清单项入库」接口，P2 一并补齐 |
| 批次丢弃 | 可选记「损耗」支出 | 由实例设置 `finance_loss_enabled` 控制，默认开 |
| 手动调整/盘点盈亏 | 不自动记账 | 盘点属库存修正，避免重复计入消费 |

- 幂等：`uq_fin_tx_ref`（仅对 `deleted_at=''` 生效）保证重复入库、重复点击不会重复记账；若用户手动删除该笔账，唯一约束随之释放，再次入库可重新生成。
- 库存批次有两个写入入口——`CreateItem` 带首批次、`AddBatch` 追加批次——两处都要触发记账。
- 删除库存批次**不级联删除**交易（历史账目保留），仅在交易备注标注来源已删除。

## 5. 后端 API

统一挂在 `/api/v1/finance/*`，信封与鉴权同现有接口。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/finance/accounts` | 账户列表（含实时余额） |
| POST/PUT/DELETE | `/finance/accounts[/{id}]` | 账户增改删；DELETE 时有流水自动转为归档（`archived=1`），无流水才真删 |
| GET | `/finance/categories?type=` | 分类树 |
| POST/PUT/DELETE | `/finance/categories[/{id}]` | 分类增改删 |
| GET | `/finance/transactions?month=&type=&account=&category=&q=&page=` | 分页流水 |
| POST/PUT/DELETE | `/finance/transactions[/{id}]` | 记账/改账/软删除 |
| POST | `/finance/transactions/{id}/restore` | 恢复软删除 |
| POST | `/finance/transfer` | 账户间转账（单条 `type='transfer'`：`account_id` 转出、`to_account_id` 转入） |
| GET | `/finance/stats?month=` | 收支合计、分类占比、账户余额、预算进度 |
| GET | `/finance/trend?months=6` | 近 N 月收支趋势 |
| GET/PUT | `/finance/budgets?month=` | 预算查询/设置 |
| GET | `/finance/export?month=` | 导出 CSV |
| POST | `/finance/recognize` | 账单截图 → 候选交易（P3） |

新增文件：`store/finance_repo.go`、`api/handler/finance.go`、`ha/finance_sync.go`。

## 6. 接入 Home Assistant

复用 `stickykee_server_<instance_id>` 虚拟设备，经 mobile_app webhook 的 `register_sensor` / `update_sensor_states` 发布实体，与生日、库存、计划同一套机制。

**统一注册**：所有服务端实体（生日 / 记账 / 库存 / 计划）共用 `ServerDevice`（`server_device.go`）持有的**唯一**注册与 webhook，登记在实例级 `prefs` 的 `server_device_reg_<instance_id>`。不要各模块自行注册：HA 以 `(app_id, device_id)` 作为 mobile_app 配置条目唯一键，同一键再次注册会**轮换 webhook_id** 并让旧 webhook 立即失效，多模块各自注册会互相踢掉对方的 webhook，表现为反复重注册、实体抖动与设备分裂。

**实体（默认发布 4 个）：**

| 实体 | unique_id | 状态 | 属性 |
|---|---|---|---|
| `sensor.hc_finance_expense` | `hc_fin_expense` | 本月支出（元） | `by_category` 分类合计 |
| `sensor.hc_finance_income` | `hc_fin_income` | 本月收入（元） | — |
| `sensor.hc_finance_budget_left` | `hc_fin_budget_left` | 本月预算剩余（元） | `usage_pct` |
| `sensor.hc_finance_balance` | `hc_fin_balance` | 总资产（元） | `by_account` 各账户余额 |

- **单位**：后端以「分」计算，发布前统一 `/100` 并保留 2 位小数，避免把 3280 分发成 3280 元。
- **entity_id 以注册返回为准**：实际实体名受 HA slugify 与设备名影响，上表为期望值，前端与自动化不得硬编码。
- **推送触发点**：新增/编辑/软删除/恢复交易、转账、预算变更、库存自动记账，均触发 5s 去抖重算；每小时全量校准一次，沿用库存同步节奏。
- **预算超支**：`budget_left < 0` 时，除更新传感器外，额外推送一条 `persistent_notification`（`notification_id = hc_fin_budget_<month>_<category_id>`，按月+分类去重），正文给出超支金额；同时可触发 HA 事件 `stickynuo_finance_budget_exceeded` 供自动化订阅。
- **权限**：注册与推送使用管理员 HA Token（与库存同步一致），普通用户无需配置。
- **实体数量**：固定 4 个，不随账单增长新增实体，避免 HA 实体膨胀。

| 阶段 | 内容 |
|---|---|
| P1 | 5 张表 + 账户/分类/交易 CRUD + 库存批次自动记账（新建/丢弃）+ 本月概览 + HA 4 传感器 |

## 9. 风险与约束

- **金额精度**：全链路用分（INTEGER），前端展示时除以 100；禁止用 float 参与计算。
- **重复记账**：依赖 `uq_fin_tx_ref`（仅对未删除交易生效）+ `INSERT OR IGNORE`；库存侧删除不级联删账。
- **并发**：SQLite 单写，转账在事务内写单条 `transfer` 记录并校验转出账户余额不为负（信用卡允许负）。
- **隐私**：金额属敏感数据，仅同 `instance_id` 可见；导出接口需登录，日志不打印金额明细。
- **统计一致性**：所有统计只算 `deleted_at=''`；软删除保留 30 天可恢复。
- **实例删除**：五张表均通过外键 `ON DELETE CASCADE` 随实例清理。
- **分类映射**：库存 `category` 到财务分类走默认映射表，未命中落「其他支出」，映射可在设置中调整。
- **转账口径**：转账不计入收支统计，只影响账户余额。
- **币种**：P1–P2 仅支持 CNY，`currency` 字段预留，P3 再补汇率与折算。
- **权限**：本人可增改自己的账目；删除/修改他人账目仅管理员。
- **周期账单**：在每小时 ticker 内生成，按 `last_run_month` 去重，跨月补生成一次。
