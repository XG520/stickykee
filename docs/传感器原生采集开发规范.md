# 传感器原生采集上报开发规范

> 版本：v1.4.0 起强制生效
> 适用范围：本仓库全部客户端（`apk/android` 原生工程 + `app` 前端）

## 1. 强制要求

1. **APK 端所有传感器数据的采集与上报，必须由原生（Java）实现**，不得在 WebView 内用浏览器 API 采集后上报。
2. **后续新增的任何传感器，必须默认按本规范接入原生采集链路**；采用非原生实现（`navigator.*`、WebView 定时器、`evaluateJavascript` 注入回传等）一律不予合入。
3. 前端（JS）在 APK 内**只负责配置与展示**：同步采集上下文、渲染开关面板、展示上报结果；不再承担采集与上报职责。
4. 所有客户端上报的数据格式与接口协议必须**完全一致**（见第 3、4 节）。
5. 本规范为代码审查强制校验项，审查清单见第 8 节。

### 唯一例外：Web 降级路径

纯浏览器（非 APK）环境没有原生能力。此时允许保留浏览器 API 采集实现作为**降级路径**，但必须满足：

- 仅在 `window.StickyKeeNative`（APK 原生桥）不存在时启用；
- 代码中标注 `// Web 降级：APK 内不使用（见 docs/传感器原生采集开发规范.md）`；
- 数据格式必须与原生实现完全一致（同一 key、同一 state 类型与枚举）。

## 2. 统一架构

```
[前端] 配置与展示
   │  setSensorContext(地址, token, 实例, 设备ID, 设备名, 启用项, 追踪开关)   ← 桥调用
   │  setSensorInterval(秒)
   ▼
[原生] NativeSensorReporter  ← 统一采集器 + 统一上报器
   │  保活服务 KeepAliveService 按 interval 心跳调用（前台/后台同一链路）
   │  采集 → 组装 payload → POST 上报
   ▼
[服务端] POST /api/v1/instances/{id}/sensors/report
   │  按 sensor_config 二次过滤 → mobile_app webhook → Home Assistant
   ▼
[HA] 实体更新
```

关键点：**上报由原生定时驱动，不依赖 WebView 存活**。WebView 被系统节流/冻结、应用被划掉时，前台服务仍在按周期上报（与官方 App 一致）。

## 3. 统一数据格式

### 3.1 上报请求体

```json
{
  "device_id": "<稳定设备ID>",
  "device_name": "<设备显示名>",
  "manufacturer": "<厂商>",
  "model": "<型号>",
  "os_name": "android",
  "os_version": "<Android 版本号>",
  "sensors": {
    "<key>": { "state": <number|string>, "attributes": { } }
  }
}
```

- `sensors` 为**对象**，键为传感器 key，值为下述 `sensorValue`；
- 未采集到的传感器**整个键不出现**（不得上报 `null`/空串占位）；
- `attributes` 可选，无属性时省略。

### 3.2 sensorValue

| 字段 | 类型 | 说明 |
|---|---|---|
| `state` | `number` \| `string` | 传感器状态值；数值型不要带单位 |
| `attributes` | `object`（可选） | 附加信息（坐标、精度、带宽等） |

### 3.3 值域表（与 `server/internal/api/handler/sensors.go` 的 `SENSOR_DEFS` 一一对应）

| key | state 类型 | 取值 / 单位 | attributes | 原生数据源 |
|---|---|---|---|---|
| `battery_level` | number | 整数 0~100（%） | — | `BatteryManager.GET_PROPERTY_CAPACITY` |
| `battery_state` | string | `charging` / `discharging` / `full` | — | `ACTION_BATTERY_CHANGED`（`level>=scale` 或 `STATUS_FULL` 判 `full`） |
| `connection_type` | string | `wifi` / `cellular` / `ethernet` / `unavailable` | — | `ConnectivityManager.getNetworkCapabilities` |
| `network_quality` | string | `5g` / `4g` / `3g` / `2g` / `wifi` / `ethernet` / `unavailable` | `downlink_kbps`, `upstream_kbps`（可选） | `TelephonyManager` / `NetworkCapabilities` |
| `wifi_ssid` | string | 当前 Wi-Fi 名称（已去除引号） | — | `WifiManager.getConnectionInfo` |
| `bssid` | string | 接入点 MAC | — | `WifiManager.getConnectionInfo`（无效值 `02:00:00:00:00:00` 不上报） |
| `screen_state` | string | `on`（应用在前台）/ `off`（应用退后台） | — | `MainActivity.foreground` 静态标记 |
| `light_sensor` | number | 整数 lux | — | `SensorManager TYPE_LIGHT` |
| `proximity` | string | `near` / `far` | `distance`, `max_range` | `SensorManager TYPE_PROXIMITY` |
| `public_ip` | string | IPv4 字符串 | — | HTTP 多源探测（ipify 等 4 源，5 分钟缓存） |
| `current_time_zone` | string | IANA 时区名（如 `Asia/Shanghai`） | `offset`（小时，可含小数） | `TimeZone.getDefault()` |
| `last_update_trigger` | string | `periodic`（周期心跳）/ `manual`（手动触发） | — | 上报入参 |
| `app_version` | string | 应用版本号（取 `versionName`） | — | `PackageManager.getPackageInfo` |
| `geocoded_location` | string | 逆地理地址文本 | `latitude`, `longitude`（设备原始坐标） | `LocationManager` + 系统 `Geocoder` |

> 值域变更说明：`network_quality` 由原前端的 `effectiveType`（Wi-Fi 下也报 `4g`）改为**按网络传输类型与蜂窝制式取值**，语义更准确；`proximity` 由原「环境光阴影启发式」改为**真实接近传感器**。两者均以上表为准。

## 4. 上报接口协议

- **接口**：`POST /api/v1/instances/{instanceId}/sensors/report`
- **鉴权**：`Authorization: Bearer <会话 token>`
- **请求头**：`Content-Type: application/json`
- **超时**：连接 10s / 读取 15s
- **成功响应**：`{"data":{"registered":true,"reported":N}}`
- **失败处理**：
  - `401` / `403`（会话失效）→ 清空本地采集上下文，等待前端重新同步；
  - 其他错误（网络异常、后端不可达）→ 静默保留上下文，下个心跳自动重试，**不得抛出**。

## 5. 原生实现规范

### 5.1 职责划分

- **单一采集器**：全部传感器采集集中在 `NativeSensorReporter` 一个类内，禁止在各业务类里零散采集。
- **单一上报出口**：仅由该类组装 payload 并上报。
- **采集范围**：只采集前端同步过来的**启用项清单**（`sensor_config`），未启用项不采集（避免无谓的定位/公网请求）。

### 5.2 上下文同步协议（桥方法，`NativeBridge`）

| 桥方法 | 签名 | 说明 |
|---|---|---|
| `setSensorContext` | `(baseUrl, token, instanceId, deviceId, deviceName, enabledKeysCsv, tracking)` | 前端在登录、实例切换、启用项变化、追踪开关变化时调用；调用后立即触发一次上报 |
| `clearSensorContext` | `()` | 登出/会话停止时调用 |
| `setSensorInterval` | `(sec)` | 上报间隔（10~3600 秒），落 SharedPreferences 并重排保活心跳 |
| `getSensorInterval` | `() -> int` | 读取当前间隔 |
| `reportSensorsNow` | `(trigger, req)` | 手动即时上报，结果经 `stickykee-sensors` 事件回传 `{req, ok, reported, error}`（`req` 用于前端请求/响应配对） |
| `requestBackgroundLocation` | `()` | 申请后台定位权限（Android 11+ 走系统设置引导） |

上下文持久化于 `SharedPreferences("stickykee")`：`sensor_ctx_url/token/inst/dev/devname/keys/track/on`、`sensor_last_report`、`sensor_last_loc`。

### 5.3 权限与前台服务

- 必声明权限：`ACCESS_NETWORK_STATE`、`ACCESS_WIFI_STATE`、`ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION`、`ACCESS_BACKGROUND_LOCATION`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`、`FOREGROUND_SERVICE_LOCATION`。
- 保活服务声明：`android:foregroundServiceType="dataSync|location"`，并以 `FOREGROUND_SERVICE_TYPE_DATA_SYNC | FOREGROUND_SERVICE_TYPE_LOCATION` 启动前台。
- 登录后除通知权限外，必须引导申请**后台定位**（否则退后台无法刷新 `geocoded_location`）。

### 5.4 异常与边界（强制）

1. 每个传感器的采集**逐项 try-catch**，单项失败只跳过该项，不得影响其他传感器；
2. 上报线程与保活心跳线程**原子防重入**（`AtomicBoolean`）；
3. 所有对外方法**不得抛出异常**（保活服务绝不能被拖崩）；
4. 定位失败/无 fix/无权限 → 不上报该项（严禁用网络定位顶替卫星定位，避免「地址与坐标不一致」）；
5. 上下文不完整（缺 URL/token/实例/设备）→ 直接返回，不做任何网络请求；
6. 上报成功必须刷新 `sensor_last_report` 时间戳，作为链路健康判据；
7. 壳页（`location.hostname === 'localhost'`）不得写入上下文。

## 6. 新增传感器接入步骤（Checklist）

1. 在 `server/internal/api/handler/sensors.go` 的 `SENSOR_DEFS` 注册（key/name/icon/unit/device_class/label/desc）；
2. 在前端 `app/src/utils/sensors.js` 的 `availableSensors()` 与 `unavailableReason()` 声明可用性与置灰原因；
3. 在 `NativeSensorReporter.collect()` 增加**原生**采集分支（按 key 判断，采不到就不 put）；
4. 在本文档第 3.3 节值域表登记 state 类型与枚举；
5. 若需新权限，同步更新 `AndroidManifest.xml` 与第 5.3 节；
6. 编译级验证通过（Java `javac` + 前端 `esbuild`）；
7. 真机验证前台/后台均能在 HA 中看到该实体周期更新。

## 7. 反例（禁止写法）

```js
// ❌ 禁止：在 APK 内用浏览器 API 采集（WebView 退后台即失效）
if (enabled.has('battery_level')) {
  const b = await navigator.getBattery()
  sensors.battery_level = { state: Math.round(b.level * 100) }
}

// ❌ 禁止：用注入 JS 驱动采集上报（WebView 被冻结即断链）
wv.evaluateJavascript("window.__sensorTick && window.__sensorTick()", null)

// ❌ 禁止：各业务类里零散采集、自行拼接 payload
```

```java
// ❌ 禁止：在心跳线程里用注入 JS 驱动采集（WebView 被冻结即断链，且拖垮保活）
NativeBridge.tickSensorsFromService(); // 已删除，仅作反例
// ✅ 正确：交给 NativeSensorReporter（内部起独立线程 + 原子防重入）
NativeSensorReporter.report(ctx, "periodic");
```

## 8. 代码审查强制校验清单

审查任何涉及传感器的变更时，逐条确认：

- [ ] 采集是否全部在 `NativeSensorReporter` 内、且为原生数据源？有无 `navigator.*` / 浏览器 API 参与 APK 采集？
- [ ] 上报是否由原生直连 `/sensors/report`？有无经 WebView（`evaluateJavascript`）或 JS 定时器驱动？
- [ ] 新增传感器是否已在 `SENSOR_DEFS`、`availableSensors()`、值域表三处登记？
- [ ] 数据格式是否与第 3 节完全一致（key、state 类型、枚举、attributes）？
- [ ] 采不到的项是否**整个键不出现**（而非 `null`/空串）？
- [ ] 逐项 try-catch、原子防重入、方法不抛出是否满足？
- [ ] 是否只采集启用项？是否遵守 401 清上下文、成功刷时间戳？
- [ ] 若涉及新权限/前台服务类型，Manifest 与文档是否同步更新？
- [ ] Web 降级分支是否被明确标注且仅在无原生桥时生效？

## 9. 验证方法

**编译级**

```bash
# Java（改动文件）
javac -encoding UTF-8 -cp "<android.jar>:<androidx classes.jar 目录>:app/build/intermediates/javac/debug/classes" \
  apk/android/app/src/main/java/cn/stickykee/app/NativeSensorReporter.java \
  apk/android/app/src/main/java/cn/stickykee/app/KeepAliveService.java \
  apk/android/app/src/main/java/cn/stickykee/app/NativeBridge.java
# 前端
cd app && ./node_modules/.bin/esbuild src/utils/autoSync.js --outfile=/tmp/x.js --format=esm
# 后端
cd server && go build ./...
```

**真机（前台 / 后台）**

| 场景 | 步骤 | 预期 |
|---|---|---|
| 前台 | 打开应用停在首页 | HA 中电量等实体按配置间隔周期更新 |
| 退后台 | 按 Home 键 / 熄屏数分钟 | 实体仍周期更新，`last_update_trigger` = `periodic` |
| 划掉应用 | 从最近任务划掉，等 1~2 分钟 | 前台服务存活，实体继续更新 |
| 后台定位 | 授予「始终允许」定位，退后台移动 | `geocoded_location` 地址随位置更新 |
| 手动上报 | 设置页点「立即上报」 | 实体立即刷新，`last_update_trigger` = `manual` |
| 对照 | 与官方 HA App 同场景对比 | 数值一致、无停滞/延迟更新 |

## 10. 例外与已知限制

- **Web 端**：无原生能力，保留浏览器采集作降级（第 1 节唯一例外）。
- **device_tracker（设备追踪）**：属于定位追踪功能，不在 `SENSOR_DEFS` 传感器集合内，其自动上报仍由前端链路承担；后台刷新能力受 WebView 存活限制。若后续要求其后台实时，按第 2、5 节同样改为原生上报。
