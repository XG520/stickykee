# 生活模块多页面重构设计（移动端 APK）

- 版本：v1.0（2026-11-26）
- 范围：`生活`（库存、购物清单、账本）的页面架构与移动端交互重构
- 配套原型：[life-module-prototype.html](./life-module-prototype.html)（浏览器打开即可点击体验）
- 约束：不新增全局一级导航；保留现有主题令牌、Material Symbols 图标体系与全部业务接口

---

## 0. 结论摘要

1. **生活页从「一个大页面」改为「一个入口页 + 三个独立页面」**：`/inventory` 只做聚合入口，库存、购物清单、账本各自独立路由。
2. **账本升级为独立子应用**：`/inventory/finance/*` 内使用类似鲨鱼记账的专属底栏「明细 / 图表 / 记账（中央 FAB） / 计划 / 我的」，进入后隐藏全局 7 项底栏，顶部保留返回生活。
3. **「记一笔」从三步弹窗改为全屏数字键盘页**：分类九宫格 + 金额键盘 + 账户/支付方式/日期/备注，一屏完成。
4. **一屏一主任务**：月份与流水归明细，图表归图表，预算与周期归计划，账户/分类/导入导出归我的。
5. **补齐移动端基础体验**：安全区、44px 触控、16px 页边距、12–32px 字号阶梯、触感反馈、层级返回、加载/空/错状态。

## 1. 现状诊断

| # | 问题 | 具体表现 |
|---|------|----------|
| 1 | 三级内容平铺在一页 | `InventoryView` 顶部三段 tab 下，库存/购物/账本都是重内容页，切换只是页内替换，没有路由层级、没有返回语义 |
| 2 | 账本单页职责过载 | `FinanceHome.vue` 一屏内同时有月份切换、7 个工具按钮、搜索、分类筛选、标签筛选、4 张概览卡、日历、预算、报表、按日流水、5 个弹窗 |
| 3 | 工具入口噪声大 | 「预算/日历/报表/导出/导入/账户分类/周期」7 个同权重文字按钮横排，需横向滑动，误触与视觉负担高 |
| 4 | 筛选体系重复 | 搜索、分类下拉、标签 chips 三套筛选同时占位，用户难以判断当前生效条件 |
| 5 | 弹窗层层嵌套 | `AccountManager` 内含账户/分类/周期/自动记账 4 个 tab 和表单；`TransactionDialog` 为三步向导，手机上连续弹层 |
| 6 | 移动端细节缺失 | 页面 `px-6`（24px）偏大；10–11px 小字过多；底部导航无 `safe-area-inset-bottom`；`index.html` 未设 `viewport-fit=cover`；无触感反馈 |
| 7 | 报表能力受限 | 仅「本月分类占比 + 月度预算 + 近 6 月趋势」，缺周/年与自定义区间；后端已新增 `/finance/reports*` 与 `pay_method`，前端尚未接入 |

## 2. 设计目标与原则

**目标**：在 360–430px 宽、单手可操作的 APK 环境里，让「记账 3 秒完成、看账 1 屏读懂、管理类功能 2 层可达」。

| 原则 | 落地方式 |
|------|----------|
| 三层结构 | 全局导航（7 项）→ 生活入口（3 个模块）→ 账本子应用（5 个区） |
| 一屏一主任务 | 每个页面只保留一个「主操作」和一个视觉焦点 |
| 高频直达 | 「记一笔」固定在账本底栏正中央，任何账本页一键到达 |
| 拇指友好 | 主操作落在屏幕下半区；触控目标 ≥ 44×44；关键按钮 48–56 高 |
| 令牌化 | 颜色一律引用 `--c-*`，不硬编码；10 套主题、字体、图标风格自动跟随 |
| 渐进迁移 | 业务逻辑、API、弹窗表单不重写，只做「拆分 + 重排 + 移动端适配」 |

### 3.2 频率分层

- **P0 每天**：记一笔、看本月支出、看/改流水、勾购物项、看库存告警
- **P1 每周**：日历回看、图表、预算进度
- **P2 每月/低频**：账户与分类管理、周期账单、导入导出、自动记账、已保存报表

> 结论：把 P2 全部收进「我的」和「计划」，主流程页面只保留 P0/P1。

### 4.2 导航层级图

```
全局底栏（7 项）
└─ 生活 /inventory                     ← 生活入口（聚合）
   ├─ 库存 /inventory/stock
   ├─ 购物清单 /inventory/shopping
   └─ 账本 /inventory/finance/ledger   ← 进入后隐藏全局底栏
      ├─ 明细   （账本底栏 1）
      ├─ 图表   （账本底栏 2）
      ├─ 记一笔 （中央 FAB，全屏页）
      ├─ 计划   （账本底栏 4）
      └─ 我的   （账本底栏 5）
         ├─ 账户管理
         └─ 分类管理
```

### 4.3 底栏规则

1. **同一屏永不出现两个底栏**：`App.vue` 中全局 `MobileTabBar` 在 `route.path.startsWith('/inventory/finance')` 时隐藏；账本底栏由 `FinanceView` 渲染。
2. **账本底栏 5 个位置**：明细、图表、中央「记账」FAB、计划、我的；FAB 直径 56，上浮 16，始终可见。
3. **退出账本**：每个账本页头部左侧返回箭头 → `/inventory`；物理返回键逐级回退（add → 明细 → 生活 → 全局默认）。
4. **桌面端（≥768px）**：保留顶部 `TheNavBar`，账本改用顶部横向页签 + 右侧操作区，不显示两个底栏；账本底栏仅在移动端出现。

### 4.4 状态保持

- 账本月份（`YYYY-MM`）存入轻量 store（`sessionStorage`），明细/图表/计划共享；切 tab 不重置。
- 明细筛选条件、搜索词、滚动位置：`keep-alive` 保留；离开账本回生活时清空筛选。
- 图表页记住上次「收支类型 + 周/月/年」。
- 记一笔页草稿：仅在同一次进入内保留；返回或保存后清空。

## 5. 页面详细设计

> 以下高度均为「内容高度」，未计顶部状态栏安全区；间距基于 4pt 栅格。

### 5.1 生活入口 `/inventory`

**目标**：让用户在 1 屏内知道「家里有多少东西、要买什么、这个月花了多少」，并一步进入对应模块。

```
┌────────────────────────────┐
│ 生活                 11月26日 │  ← 标题 24/32
│ ┌────────────────────────┐ │
│ │ 本月支出      ¥3,842.60 │ │  ← 账本主卡（全宽 132）
│ │ 收入 ¥16,682  结余 +¥12,839│ │
│ │ ╱╲╱╲╱▁╱╲  近 7 天         │ │  ← 迷你折线 40 高
│ └────────────────────────┘ │
│ ┌──────────┐ ┌──────────┐  │
│ │ 库存 21 件 │ │ 待买 4 项  │  │  ← 2 列卡（各 96 高）
│ │ 临期 2 · 补货 1│ │ 预计 ¥86  │  │
│ └──────────┘ └──────────┘  │
│  扫码入库  记一笔  盘点  加购物 │  ← 4 个快捷操作（56 圆）
└────────────────────────────┘
```

- **账本主卡**：视觉焦点，支出用 32px headline 数字；收入/结余 12px 次级；折线来自 `stats.by_day`（本月最后 7 天）或 `trend`。
- **库存卡**：在库总数 + 临期/需补货角标；有告警时卡片边框 1px `error/30`。
- **购物卡**：待买数量 + 预计金额（`shopping` 数据求和）。
- **快捷操作**：56px 圆形图标按钮 + 11px 标签；`扫码入库`、`记一笔`、`盘点`、`加购物项`。
- **交互**：卡片按下 `scale(.98)` + 180ms 回弹；进入子页使用「淡入 + 上移 8px」200ms。
- **空态**：库存为 0 时库存卡显示「添加第一件物品」；无账目时主卡显示「记下第一笔」。
- **数据**：`inventoryStats()`、`inventoryShopping()`、`financeStats(month)`。
- **迁移**：新建 `InventoryHomeView.vue`；原 `InventoryView` 的三段 tab 与主体内容分别迁出。

### 5.2 库存 `/inventory/stock`

**目标**：快速查物品、处理临期/补货、扫码/拍照入库。

```
┌────────────────────────────┐
│ ← 库存            🔍   ＋添加 │  ← 头部 48
│ [搜索框（点 🔍 展开）]        │
│ ┌────────────────────────┐ │
│ │ 在库 21  价值 ¥1,286  临期 2 ›│ │  ← 概览卡 76
│ └────────────────────────┘ │
│ [全部][厨房][冰箱][储物间][⚙] │  ← 位置 chips 32
│ ⦿盘点  ⦿扫码  ⦿拍照  ⦿导出  │  ← 快捷操作 4×56
│ ┌────────────────────────┐ │
│ │ 🥛 牛奶      2 盒  临期 2 天│ │  ← 行 72
│ │ 🥚 鸡蛋     12 枚  冰箱     │ │
│ │ 🧴 洗衣液    1 瓶  需补货   │ │  ← 左侧 3px 告警条
│ └────────────────────────┘ │
└────────────────────────────┘
```

- **头部**：返回 44×44；标题 18/24；右侧搜索 44×44；「添加」为主色描边胶囊（高 36）。
- **搜索**：点击图标后标题行下展开输入框（44 高），250ms 防抖；再次点击收起。
- **概览卡**：三列数字（在库 / 价值 / 临期），「需补货 n」作为右侧跳转；避免 5 卡平铺。
- **位置 chips**：高 32、圆角 999、横向滚动，选中主色填充；末尾齿轮打开位置管理 Sheet。
- **快捷操作**：4 个 56px 圆形图标 + 11px 文案，间距 12；低频项（导出）降为 `surface-alt` 描边。
- **列表行**：高 72；图标/首字徽标 40；名称 15；副行 11（分类/位置）；右侧数量 20 tabular + 单位 11；临期/需补货用 11px 胶囊；低库存左侧 3px `error` 竖条。
- **交互**：点击行 → 物品详情 Sheet（含批次、消耗、移库、加入购物）；长按 → 快捷菜单（消耗 1 / 加入购物 / 删除）。下拉刷新。
- **状态**：骨架 3 行；空态「还没有记录物品」+ 主按钮；错误「加载失败，点击重试」。
- **数据**：`inventoryLocations`、`inventoryItems`、`inventoryStats`、`inventoryStocktake`、`inventoryExport`、`recognizeInventoryImage`、`inventoryBarcode`。

### 5.3 购物清单 `/inventory/shopping`

```
┌────────────────────────────┐
│ ← 购物清单                ＋ │
│ 已买 2 / 6    [▓▓▓░░░] 预计 ¥86│
│ ○ 牛奶        2 盒           │  ← 行 56，点击勾选
│ ○ 洗发水      1 瓶           │
│ ● 垃圾袋      1 卷（已买，灰） │
│ 已买 2 项 · 清空              │
└────────────────────────────┘
```

- 待买行：勾选框 24（热区 44×44），行高 56；点击整行切换。
- 已买分组默认置底可折叠，标题右侧「清空已买」。
- 左滑显示「删除」；点击文字进入编辑（名称/数量/备注）。
- 底部保留现有「采购入库」入口，作为列表末尾的整行按钮，不做悬浮按钮，避免与全局底栏冲突。
- 数据：`inventoryShopping`、`addInventoryShopping`、`updateInventoryShopping`、`checkInventoryShopping`、`deleteInventoryShopping`、`purchaseShoppingItem`。

### 5.4 账本容器与明细 `/inventory/finance/ledger`

**容器 `FinanceView.vue`**：`<router-view>` + `FinanceTabBar`；页面自有头部（各 tab 标题不同）。

```
┌────────────────────────────┐
│ ← 账本            🔍  ☰筛选  │  ← 头部 48
│ ‹  2026年11月  ›   [本月]    │  ← 月份条 40
│ ┌────────────────────────┐ │
│ │ 本月支出                 │ │
│ │ ¥3,842.60              │ │  ← 32px 主数字
│ │ 收入 ¥16,682 · 结余 +¥12,839│ │
│ │ 预算 [▓▓▓▓▓░░░] 剩余 ¥1,157│ │  ← 有预算才显示
│ └────────────────────────┘ │
│ [11-26 ● 全部] [分类:餐饮] × │  ← 仅激活筛选时出现 32
│ 今天 · 支出 ¥236.80          │  ← 吸顶日头 32
│ ┌────────────────────────┐ │
│ │ 🍜 餐饮  午饭 · 微信     -¥28.00│ │  ← 行 60
│ │ 🚇 交通  地铁 · 支付宝   -¥6.00 │ │
│ └────────────────────────┘ │
└────────────────────────────┘
        [明细] [图表] (＋) [计划] [我的]
```

- **汇总卡**：支出为主视觉；收入用 `--c-accent`；结余为收支差；预算进度条仅在 `budget_total > 0` 时出现。总资产移到「我的」。
- **月份条**：左右箭头 44×44；点击月份文字打开月份选择 Sheet（P1）；非本月显示「本月」chip。
- **筛选**：`☰` 打开筛选 Sheet（类型/分类/账户/支付方式/标签），应用后以可删除 chips 回显；分类下拉、标签行不再常驻。
- **搜索**：点击 🔍 后头部变为搜索输入框（44 高），提示「搜索全部月份」；输入 250ms 防抖，清空恢复。
- **列表**：按日分组，日头吸顶（`sticky top-[header]`），显示「今天/昨天/11月24日 周一」+ 当日支出；行高 60，图标 36，标题 14，副行 11（账户 · 备注 · 标签 · 支付方式），金额 15 tabular，收入 `accent` 前缀 `+`。
- **无限滚动**：每页 60，触底加载；末尾「已加载全部」；切换筛选回到顶部。
- **行交互**：点击 → 记一笔页（编辑模式，预填）；右侧 `⋯` → 动作 Sheet（编辑 / 复制一笔 / 删除）；删除二次确认。
- **日历**：头部日历图标打开 Sheet：月历 + 每日收支小字 + 今日描边；点选某天 → 关闭 Sheet、列表加「11-26」筛选 chip。
- **手势**：列表下拉刷新；左滑行显示删除（P1）。不做整页左右滑动切月份，避免与系统返回手势冲突。
- **状态**：骨架 4 行；空态区分「本月无账目 / 搜索无结果 / 该日无账目」；接口错误显示重试。

## 6. 移动端交互规范

### 6.1 尺寸与安全区

| 项目 | 规范 |
|------|------|
| 设计基准 | 360×800 / 390×844 / 412×915，内容宽度 100% |
| 页面左右边距 | 16px（替代现有 24px）；卡片内边距 16px |
| 顶部安全区 | `padding-top: env(safe-area-inset-top)`，`index.html` 增加 `viewport-fit=cover` |
| 底部安全区 | 所有固定底栏 `padding-bottom: env(safe-area-inset-bottom)`；内容区底部预留 `底栏高 + 16 + safe` |
| 全局底栏 | 高 64 + safe-bottom |
| 账本底栏 | 高 60 + safe-bottom；FAB 56，上浮 16 |
| 账本内容底部留白 | 60 + 16 + safe-bottom（有 FAB 时 76） |
| 最小触控 | 44×44；图标按钮视觉 40、热区 44；列表行 ≥ 56 |
| 关键按钮 | 保存 44 高；FAB 56；键盘键 56 |

### 6.2 字号与文本

| 层级 | 字号/行高 | 用途 |
|------|-----------|------|
| 金额主数字 | 32/38 | 明细支出、图表总额 |
| 记账输入 | 40/44 | 记一笔金额 |
| 页面标题 | 18–20/26 | 头部标题 |
| 卡片标题 | 15/20 | 卡片与列表主文本 |
| 正文/输入 | 14/20 | 表单、按钮 |
| 辅助 | 12/16 | 账户、备注、说明 |
| 标签/角标 | 11/14 | Chips、图表轴、徽标 |
| 最小 | 10/13 | 仅用于环形图内圈等非关键信息 |

- 金额一律 `font-variant-numeric: tabular-nums`，避免跳动。
- 中文正文行高 ≥ 1.45；单行截断用省略号，副行最多 1 行。
- 支持系统字号放大 115% 不裁切：容器用 `min-height` 而非固定高度，文本不绝对定位。

### 6.3 手势与反馈

| 场景 | 反馈 |
|------|------|
| 点击卡片/按钮 | 160ms `scale(.97)` 或底色变化；抬起恢复 |
| 切换底栏 | 图标由描边变填充，标签变主色，200ms |
| 页面进入（子页） | 上移 8px + 淡入 200ms；返回反向 160ms |
| 记一笔页 | 从底部上滑 240ms（全屏 Sheet 语义） |
| 保存成功 | 10ms 震动 + toast 1.6s + 返回 |
| 删除 | 弹确认 Sheet（危险操作主色变 `error`），完成后 toast 可撤销（P1） |
| 下拉刷新 | 顶部 24px 指示器，触发阈值 64px，最长 800ms |
| 左滑行 | 露出 72px 删除按钮（P1） |
| 长按行 | 打开动作 Sheet（编辑/复制/删除） |
| 键盘 | 数字键 10ms 震动；长按 ⌫ 400ms 后连续清除 |

- 所有交互必须有视觉或触觉反馈，不允许「点了没反应」。
- 操作中（保存/删除/导入）按钮进入 loading 并禁用重复点击。

### 6.4 状态与异常

- **加载**：首屏骨架屏（列表 4 行、卡片占位），不出现整页 spinner。
- **空态**：图标 48 + 一句说明 + 主操作按钮，按场景区分文案。
- **错误**：行内错误条 + 「重试」按钮；不弹窗打断。
- **离线 / 服务器不可达**：顶部细条提示，保持本地已加载数据；记一笔保存失败时保留草稿并提示重试。
- **表单校验**：即时校验 + 顶部/字段旁 12px 错误文案，禁止仅靠颜色。
- **退出保护**：记一笔有输入时返回需确认。

### 6.5 返回与深链

- 所有子页头部固定返回箭头，语义为「上一级页面」，不依赖浏览器历史猜测。
- Android 物理返回：add → 来源 tab；库存/购物 → 生活；账本 tab → 生活；生活 → 系统默认。上线前用 Capacitor `App.backButton` 验证并补齐监听。
- 深链（如从通知进入某笔账目）：先重定向到 `/inventory/finance/add?id=`，返回落到明细页，不进入空白历史。

### 6.6 动效与性能

- 缓动统一 `cubic-bezier(.2,.8,.2,1)`；时长：按压 160ms、切换 200ms、页面 200–240ms、Sheet 260ms。
- 支持 `prefers-reduced-motion`：关闭位移与缩放，只保留透明度。
- 避免大面积 `backdrop-filter` 与持续动画；底栏使用 95% 不透明底色 + 1px 边框即可。
- 列表超过 300 行启用虚拟滚动（P1），首屏只渲染可视区 + 1 屏缓冲。

## 7. 视觉设计规范

### 7.1 颜色令牌（禁止硬编码）

全部沿用 `src/assets/main.css` 与 `src/themes.js` 的令牌，原型与实现只引用变量：

| 令牌 | 默认主题值 | 用途 |
|------|------------|------|
| `--c-background` | #0E0F12 | 页面底色 |
| `--c-surface` | #1E1F22 | 卡片、底栏 |
| `--c-surface-alt` | #26272C | 输入框、次级按钮、Chips |
| `--c-surface-hover` | #2F3036 | 按压/悬停 |
| `--c-on-background` | #F2F0EB | 标题、主要文本 |
| `--c-on-surface` | #E8E5DD | 卡片内文本 |
| `--c-muted` | #8A8986 | 辅助文本、未选中图标 |
| `--c-faint` | #6E6D69 | 占位符、图表轴 |
| `--c-border` | #34353A | 描边、分隔线 |
| `--c-primary` | #F5A623 | 主操作、支出、选中态 |
| `--c-accent` | #5EC4B0 | 收入、增长、辅助强调 |
| `--c-error` | #E85D4C | 超支、删除、告警 |
| `--c-warning` | #E8A84C | 临近阈值 |
| `--c-info` | #6BA3D9 | 中性提示 |

- 语义约定：**支出 = primary，收入 = accent，超支/危险 = error**；不再出现「收入用主色、支出用白色」的混用。
- 图表配色顺序：`primary → accent → info → warning → error → success`，同色系用 70%/45% 透明度做分层；超过 6 类聚合为「其他」（muted）。
- 图表颜色必须与图例文字同时出现（色弱可读）；进度条同时显示百分比数字。

### 7.2 字体

- 展示/数字：`--font-headline`（默认 Space Grotesk）；正文：`--font-body`（Source Sans 3）；中文回退系统字体。
- 主题切换（如中国风楷体）自动跟随，页面不得写死字体。
- 数字使用 tabular-nums；金额单位「¥」字号为数字的 55%，颜色 muted。

### 7.3 间距 / 圆角 / 阴影

| 项目 | 规范 |
|------|------|
| 间距阶梯 | 4 / 8 / 12 / 16 / 20 / 24 / 32 |
| 页面纵向分区 | 12–16 |
| 卡片圆角 | 16（大卡）/ 12（控件）/ 999（胶囊）/ 24（Sheet 顶部） |
| 卡片描边 | 1px `--c-border`；不加默认阴影（暗色主题靠描边分层） |
| 浮层阴影 | `0 12px 32px rgb(0 0 0 / .45)`（Sheet、FAB） |
| 分隔线 | 1px `--c-border`，不缩进或左缩进 16（列表内） |

### 7.4 图标

- 统一 Material Symbols Outlined，移动端 20/24/28 三档；选中态使用 FILL 1。
- 图标按钮视觉 40×40、热区 44×44；底栏图标 24 + 标签 10–11。
- 分类图标沿用后端返回的 `icon` 字段，缺失时按类型回退 `label` / `payments`。

### 7.5 金额与数据展示

- 明细与表单显示两位小数；图表总额与排行榜可用整数/万单位（≥10000 显示「x.x万」）。
- 负数（支出）用 `-` 前缀 + 主色；正数（收入）用 `+` 前缀 + accent；转账不显示正负。
- 大额数字不换行，必要时缩小 1 档而不是截断。
- 日期：今天/昨天/「11月24日 周一」；时间 HH:mm。

### 7.6 桌面端

- ≥768px：保留顶部导航与 24px 页边距；账本使用顶部横向页签（明细/图表/计划/我的）+ 右上「记一笔」主按钮。
- 列表最大宽度 720，图表两列排布（环形图 + 排行左、趋势右）。
- 移动端底栏在桌面端隐藏（现有 `md:hidden` 逻辑保留）。

### 7.7 可访问性

- 文本对比度：正文 ≥ 4.5:1，大字/图标 ≥ 3:1（沿用现有令牌已达标）。
- 所有图标按钮提供 `aria-label`；开关使用 `role="switch"` + `aria-checked`。
- 焦点可见：`outline: 2px solid var(--c-primary)` + 2px 偏移，仅在键盘导航时显示。
- 不依赖颜色传达状态：超支同时显示「已超支 ¥x」。

### 9.6 性能与包体

- 路由级懒加载已具备，新增页面继续使用动态 import；账本与库存 chunk 分离。
- 明细列表首屏 60 条，触底加载；超过 300 条启用虚拟滚动（P1）。
- 图表用原生 SVG，不引入图表库；环形图/折线图各一个轻组件。
- 图片（物品照片）使用 `loading="lazy"` + 固定宽高比，避免布局抖动。
- 记录页面切换耗时（APK 低端机 4GB 内存）作为验收项，目标 < 300ms。

## 12. 风险与取舍

| 风险 | 说明 | 取舍 |
|------|------|------|
| 双层底栏混淆 | 全局底栏与账本底栏切换 | 进入账本即隐藏全局栏，头部固定返回；首次进入可用一次性提示说明 |
| 页面数量增加 | 路由与组件变多 | 复用现有弹窗逻辑与接口，先拆页面不改业务；保留 keep-alive 降低感知 |
| 周/年数据不完整 | 后端缺区间序列接口 | P0 只做月视图，周/年入口标注「即将上线」，P1 补接口后开放 |
| 支付方式历史数据为空 | 旧流水无 `pay_method` | 明细不展示空值；筛选项「未记录」单独一档 |
| 桌面端双导航 | 现有顶部导航 + 桌面页签 | 账本底部栏仅移动端渲染，桌面用顶部页签 |
| 改造成本集中 | 一次替换生活入口风险高 | 按 9.7 顺序灰度：先并行保留旧入口，验收后再删除旧组件 |
